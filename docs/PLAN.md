# План — этап 3: DLL со статическим CRT

Цель этапа — из `docs/ROADMAP.md`: кроме статических библиотек собирать DLL, которые тоже
зависят только от системных DLL Windows, тестировать их и выпускать в релизе.

- [x] Оверлейные триплеты `triplets/<arch>-windows-dll-mt.cmake` (DLL + статический CRT),
      подключены через `vcpkg-configuration` в `vcpkg.json`.
- [x] `ci.yml`: сборка и smoke по двум вариантам линковки — `static` и `dll-mt`.
- [x] `smoke/run.ps1 -Linkage`: для `dll-mt` — `applink.c` в exe, DLL рядом с exe; архитектура
      и импорты проверяются у exe и у каждой DLL (только системные DLL; exe обязан
      импортировать `libcrypto` и `libssl`).
- [x] `smoke/smoke.c`: ошибки печатаются без передачи `FILE*` в библиотеку; новая проверка —
      BIO на stdout приложения (в DLL-варианте она проходит только через applink).
- [x] Ревизия сборки `release/revision` в теге: `openssl-<версия>-port<N>-r<ревизия>`.
      Первый релиз с DLL — r2: релиз `openssl-3.6.5-port2` той же версии порта уже есть.
- [x] Прогон зелёный, релиз с 6 архивами проверен.
- [x] `CLAUDE.md`, `docs/STATUS.md`.
- [ ] По просьбе владельца: у каждой сборки своя проверочная джоба, которая стартует сразу
      после этой сборки, а не после всей матрицы. Пара «build → smoke» вынесена
      в переиспользуемый `build-and-test.yml`, `ci.yml` вызывает его по матрице; smoke проверяет
      Debug и Release шагами одной джобы. Заодно: в разборе импортов `dumpbin` у DLL в список
      попадала строка `Dump of file …dll`.
