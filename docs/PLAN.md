# План — этап 4: функциональные тесты

Цель этапа — из `docs/ROADMAP.md`: проверять не только «библиотека живая», но и базовую
функциональность — эталонные векторы, асимметрию с негативными случаями, провайдеры и потоки.
Владелец выбрал эти три направления (2026-10-17); PKI, расширенный TLS, проверка упаковки через
CMake и полный набор тестов OpenSSL пока не нужны.

- [ ] `smoke/functional.c`, эталонные векторы — только из первоисточников, не по памяти:
      SHA-1, SHA-256, SHA-512, SHA3-256 от `"abc"`; HMAC-SHA-256/512 (RFC 4231, случай 2);
      AES-128-CBC (RFC 3602, случай 2); AES-256-GCM с AAD (NIST CAVP); ChaCha20-Poly1305
      (RFC 8439, 2.8.2); HKDF (RFC 5869, A.1); PBKDF2-HMAC-SHA-256 (RFC 7914, раздел 11);
      X25519 (RFC 7748, 6.1); Ed25519 (RFC 8032, TEST 2).
- [ ] Асимметрия и негативные случаи: RSA-2048 PSS и OAEP, ECDSA и ECDH P-256; отказ на
      испорченных подписи, сообщении, шифртексте, теге и на чужом ключе.
- [ ] Провайдеры: `default`, `legacy` с MD4 (RFC 1320). В статической сборке `legacy` встроен
      в `libcrypto` (порт собирает с `no-module`), в DLL-сборке это `legacy.dll` — тест печатает,
      откуда он загрузился. Потоки: несколько потоков с первого обращения к OpenSSL параллельно
      хешируют, подписывают и берут случайные числа.
- [ ] `smoke/run.ps1` собирает и запускает обе программы, проверяет обе; Debug и Release.
- [ ] Векторы прогнаны локально против OpenSSL контейнера, хеши — ещё и против встроенных
      модулей Python; негативный прогон с испорченными векторами падает.
- [ ] Прогон CI зелёный, логи прочитаны; `CLAUDE.md`, `docs/STATUS.md`.
