# Журнал знаний

## 2026-10-17 — что на самом деле лежит в статических библиотеках

- **Гипотеза.** Триплеты `-static` дают объектники, жёстко привязанные к статическому CRT:
  потребитель с `/MD` получит LNK2038. Так было записано в `CLAUDE.md` до первой сборки.
- **Что сделали.** Скачали артефакты run 1 на всех трёх архитектурах. Скриптом прочитали
  поле Machine у каждого объектника внутри `.lib` и поискали директивы `/DEFAULTLIB`.
  Ещё вытащили встроенную строку OpenSSL `compiler: ...`.
- **Что показала проверка.** Все объектники нужной архитектуры: x86 — 0x14c, x64 — 0x8664,
  arm64 — 0xaa64. Release собран с `/MT`, Debug — с `/MTd`, оба с `/Zl`. Директив
  `/DEFAULTLIB` нет ни одной: CRT в библиотеках не зашит. arm64 собран кросс-компилятором
  `Hostx64\arm64\cl.exe` из Visual Studio 18 на образе `windows-2025`. PDB нет, отладочная
  информация встроена (`/Z7`). Встроенный `OPENSSLDIR` — `C:\Program Files\Common Files\SSL`.
- **Вывод.** Гипотеза неверна: CRT выбирает компоновка потребителя. Чтобы не зависеть от DLL
  CRT, потребитель сам собирается с `/MT` / `/MTd`. `CLAUDE.md` исправлен.
